## 0단계. 전체 흐름 한눈에 보기

```
[내 PC]  코드 작성·시험 ──git push──▶ [GitHub 저장소]
                                         │  매일 07~08시(KST) 또는 버튼
                                         ▼
                                   [GitHub Actions]  뉴스 수집 → 이슈 묶기 → 통계 → Gemini 해석
                                         │  결과(data.js, DB) 커밋
                                         ▼
                                   [Render 웹서버]  자동 재배포 → 시민·의회가 보는 사이트
                                         ▲
                              관리자 /admin [최신 데이터로 갱신] 버튼 → Actions 실행
```

| 서비스 | 하는 일 | 필요한 비밀값 (넣는 곳) |
|---|---|---|
| 뉴스토어 API | 뉴스 수집 | `NEWSTORE_API_KEY` (GitHub Secrets) |
| 네이버 API HUB (선택) | 뉴스 수집 | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` (GitHub Secrets) |
| Gemini API | 통계 해석 문장 | `GEMINI_API_KEY` (GitHub Secrets), `GEMINI_TEXT_MODEL` (GitHub Variables) |
| GitHub | 코드 보관·매일 자동 실행 | — |
| Render | 웹사이트 운영 | `ADMIN_ID`, `ADMIN_PASSWORD`, `GITHUB_TOKEN`, `GITHUB_REPO`, `SESSION_SECRET` (Render Environment) |

> ⚠️ 비밀값은 **채팅·코드·README에 절대 붙여 넣지 않습니다.** 위 표의 "넣는 곳"에만 직접 입력합니다.

## 2단계. 코드 만들기 (AI 코딩 도구 사용)

`배포용 프롬프트` 문서의 **A. 마스터 프롬프트 → B. 1~7단계 프롬프트**를 순서대로 붙여 넣었습니다.
변수(`{{지역명}}` 등)는 아산시 예시값을 사용했습니다. 지역을 바꿀 때는 `asan_news/config.py` 만 고치면 됩니다.

시험 중 발견해 고친 문제 (다시 만들 때 같은 실수를 피하려면):
- 제목 앞 기자명(`홍길동 기자 =`)이 남음 → `text.py` 말머리 패턴에 추가
- 실제 DB가 비었을 때 `report` 실행 시 화면이 빈 데이터로 덮어써짐 → `export.py`에서 기사 0건이면 기존 `data.js` 유지
- 샘플 기사 링크가 존재하지 않는 주소로 열림 → 샘플일 때 "원문 없음(샘플)" 표시

| `GITHUB_TOKEN` | [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new) → Fine-grained → 저장소: `asan-news-dashboard` 만 → **Actions: Read and write** → `github_pat_...` 복사 (만료일 메모) |

## 6단계. GitHub 설정

저장소 → **Settings**

1. **Secrets and variables → Actions → Secrets** 탭 → New repository secret
   - `NEWSTORE_API_KEY`, `GEMINI_API_KEY` (네이버 사용 시 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`)
2. **Secrets and variables → Actions → Variables** 탭
   - `GEMINI_TEXT_MODEL` = `gemini-2.5-flash`
   - (주소가 다를 때만) `NEWSTORE_ENDPOINT`
3. **Actions → General → Workflow permissions** → **Read and write permissions** → Save

## 7단계. Render 배포

**권장: Blueprint로 만들기** (설정이 `render.yaml` 대로 자동 입력됨)
- [dashboard.render.com](https://dashboard.render.com) → **New + → Blueprint** → 저장소 선택 → 입력란에 값 입력 → Apply

**직접 Web Service로 만든 경우** (이번에 이렇게 만들어서 오류가 났음) → Settings에서 반드시 아래로 수정:

| 항목 | 값 |
|---|---|
| Build Command | `npm install` |
| Start Command | `node server.js` |
| Health Check Path | `/healthz` |

**Environment** 에 추가:

| Key | Value |
|---|---|
| `ADMIN_ID` | 관리자 아이디 |
| `ADMIN_PASSWORD` | 길고 복잡한 비밀번호 |
| `GITHUB_TOKEN` | `github_pat_...` |
| `GITHUB_REPO` | `asy4002/asan-news-dashboard` |
| `SESSION_SECRET` | 40자 이상 무작위 문자열 |

저장 후 **Manual Deploy → Deploy latest commit**

> 이번에 겪은 오류: `bash: line 1: start: command not found` / `Exited with status 127`
> 원인 — Start Command 가 `start` 로 되어 있었음. `node server.js` 로 바꾸면 해결.

**확인:** 로그에 `서버 시작: http://localhost:10000 (관리자: /admin)` → 상태 **Live**

## 8단계. 첫 실제 데이터 갱신

1. GitHub 저장소 → **Actions → 매일 데이터 갱신 → Run workflow**
   (또는 `https://(Render 주소)/admin` 로그인 → **[최신 데이터로 갱신]**)
2. 5~15분 후 초록 체크 + "데이터 갱신 YYYY-MM-DD HH:MM KST" 커밋 생성
3. Render 자동 재배포 → 사이트의 샘플 배너가 사라지고 실제 기사(원문 링크) 표시

**확인할 로그 문구**

| 로그 | 의미 |
|---|---|
| `[아산시] 확인 N건 · 신규 N건` | 뉴스 수집 성공 |
| `이슈 통합: 기사 N건 → 이슈 M개` | 이슈 묶기 성공 |
| `보고서 생성: AI 해석 포함` | Gemini 해석 성공 |
| `내보내기: 기사 N건 …` | 사이트용 파일 생성 |

이후에는 **매일 07:07 / 07:37 / 08:07 (KST)** 자동 실행됩니다.

## 9단계. 문제 해결 모음

| 증상 | 원인 → 해결 |
|---|---|
| 기사 제목을 눌러도 안 열림 | 샘플 데이터임 → 8단계 실행 |
| 관리자 버튼이 회색 "GITHUB_TOKEN 미설정" | Render Environment 에 `GITHUB_TOKEN` 없음 또는 오타 |
| 버튼 클릭 시 "실행 요청 실패(403)" | 토큰 Actions 권한이 Read-only, 또는 저장소 미선택 |
| 버튼 클릭 시 "실행 요청 실패(404)" | `GITHUB_REPO` 값 오류, 또는 토큰이 다른 저장소용 |
| Actions 로그 "NAVER_CLIENT_ID … 입력하세요" | 네이버 키 미등록 — 뉴스토어만 쓰면 무시해도 됨 |
| Actions 로그 뉴스토어 `HTTP 401` | `NEWSTORE_API_KEY` 값 확인 |
| Actions 로그 뉴스토어 `HTTP 404` | 주소 변경 → Variables 에 `NEWSTORE_ENDPOINT` 지정 |
| Actions 푸시 단계 403 | Workflow permissions 가 Read and write 가 아님 |
| "AI 해석 없음" | `GEMINI_API_KEY` Secret / `GEMINI_TEXT_MODEL` Variable 확인 |
| Render `status 127` | Start Command 를 `node server.js` 로 |
| 사이트 첫 접속이 느림 | Render 무료 플랜은 15분 미사용 시 잠듦 (정상) |
| `git push` 시 workflow 파일 거부 | Git 인증에 workflow 권한 없음 → GitHub 웹에서 파일 직접 수정 |
| 관리자 로그인 "잠시 후 다시 시도" | 5회 실패 시 15분 잠금 (보안 기능) |

## 참고: 검토했지만 아직 하지 않은 것

- **Gemini 구글 검색 연동 수집**: Gemini 키 하나로 실제 기사(출처 URL 포함)를 수집하는 방식. 수량이 적고 결과가 매번 달라 보조 수단으로만 적합. 필요 시 추가 개발.
- **Supabase**: 클라우드 DB. 지금 규모에서는 불필요. 기사 수작업 편집, 다중 담당자 계정, 데이터 대규모화가 필요할 때 검토.
- **Gemini로 기사 생성**: 하지 않음. 존재하지 않는 기사가 만들어질 수 있어 성과 증명용으로 부적합.
